# Bang RL runtime and application integration review

The repository implements a substantial immutable Bang environment, public-observation boundary, configurable DummyAgent, inference modules, canonical dataset writers, PPO helpers, artifact formats, and GUI-independent services. The lower-level environment and artifact tests cover many isolated contracts, but the public application path is not connected to the declared three-phase training/evaluation pipeline, and several runtime seams can silently corrupt rewards, worker state, or PPO transitions. The highest-risk findings are the no-op default training pipeline, the wrong exported evaluation implementation, and shared mutable agents across vector workers. **Watch for:** **confirmed CRITICAL** — default `TrainingService` performs simulation only and never trains PPO or saves an artifact; **confirmed CRITICAL** — `bang_rl.app.EvaluationService` bypasses the artifact-backed deterministic protocol; **confirmed CRITICAL** — `DummyVecEnv` shares each mutable agent instance across workers; **confirmed CRITICAL** — collector-calculated rewards are not copied into canonical step rewards. **Verdict**: NEEDS_CHANGES

## High-level view

The **confirmed** application training gap is above the environment layer: the service stops after collecting lightweight `EpisodeRecord` simulations, so no PPO update, canonical Parquet collection, NPZ derivation, or final inference artifact is produced unless an external runner is injected.

The **confirmed** public application evaluation seam differs from `bang_rl.evaluation.protocol`: the exported service creates RandomAgents and reports a simplified count, while the protocol module enforces artifact compatibility, balanced seats, metrics, and the 500-game deterministic contract. The documented application entry point therefore runs a different experiment.

The **confirmed** worker and learning defects are state-boundary failures. Vector workers receive the same DummyAgent objects, canonical collection can calculate rewards without persisting them as step rewards, domain `Action` dictionaries cannot be converted into `PPOTransition`, and the ledger can close an episode when only the MainAgent has been eliminated.

The remaining **confirmed** issues are lifecycle and scaling failures: primary evaluation does not close its per-game environments, direct environment construction can silently disable long-game diagnostics, public observations repeatedly serialize an unbounded event history, and JSONL reading rereads the complete file for every line.

1. **Default training is simulation-only (confirmed)** — `TrainingService._execute` never calls `PPOTrainer`, `EpisodeCollector`, Parquet/NPZ writers, or final-artifact saving, so wire the declared pipeline or reject unsupported default modes explicitly.

4. **Calculated rewards are dropped from canonical steps (confirmed)** — `EpisodeCollector.record_step` stores `values['reward']` even when it computed a `RewardBatch`, causing caches and later PPO consumers to see zero rewards; persist the acting agent’s calculated total.
5. **Domain Actions cannot enter PPO transitions (confirmed)** — `PPOTransition.from_committed` passes an `Action.to_dict()` mapping to `_action`, which calls `int(mapping)`; normalize action mappings or store the discrete action index at the ledger boundary.
6. **MainAgent elimination is treated as game termination (confirmed)** — `PendingTransitionLedger.eliminate_agent` calls `finish_episode(..., terminated=True)` even when the environment may continue; separate agent elimination from normal environment termination and retain the episode until its actual result.
7. **GAE can chain unrelated episodes/workers (confirmed)** — `PPOTrainer.update` sorts all records into one sequence and `compute_gae` has no episode/worker/rollout boundary mask; compute advantages per contiguous trajectory or add explicit reset boundaries.
8. **Primary evaluation ignores the selected opponent preset (confirmed)** — `PrimaryEvaluationProtocol.run` always uses `self.config.preset`, so validate and resolve `evaluation.opponent_preset` just as custom evaluation does.
9. **Evaluation environments and logger handlers leak (confirmed)** — `_run_game` never closes its environment, and worker/application factories pass custom loggers that the environment does not own; close both environment and supplied handlers in `finally` paths.
10. **Direct short environments silently disable diagnostics (confirmed)** — `BangEnvironment.__init__` suppresses `LongGameDiagnostics` when default thresholds exceed a short `max_episode_steps` instead of rejecting or resolving the invalid threshold configuration.
11. **Unlimited public history is reserialized on every observation (confirmed)** — `EnvironmentState.to_public` filters and converts the complete event tuple for every agent action, producing quadratic work in long episodes; cache or structurally share the immutable public projection.
12. **JSONL reading performs quadratic file I/O (confirmed)** — `runtime.logging.read_jsonl` calls `Path.read_text(...).splitlines()` again for every parsed line; read the file once and preserve the trailing-partial-line rule in memory.

### CRITICAL — Default TrainingService never trains or produces declared artifacts (**confirmed**)

`C:\Users\ozone\Desktop\GameContentsCapstone\GameContentsCapstonedesign\bang_rl\app\services.py`, `TrainingService.start` and `TrainingService._execute`, construct a `DummyVecEnv` and then loop over `run.vector.run_episodes(1, ...)`. The default path only appends `EpisodeRecord.to_dict()` values and increments counters. There is no call to `EpisodeCollector`, `ParquetCanonicalShardWriter`, `NPZTensorCacheWriter`, `PPOTrainer`, `save_phase2_inference_artifact`, or `save_final_inference_artifact`; `TrainingConfig.artifact_path` and `output_path` are only copied into progress metadata. As a result, a normal `TrainingService.start(TrainingConfig(...))` can report `finished` after simulations while producing no learned policy, no canonical dataset, no PPO updates, and no inference artifact. This violates the public training service and the Phase 1–3 contract, not merely an unimplemented optional feature.

The minimal safe fix is either to route the default path through the existing collector → split/cache → supervised → PPO → final-artifact orchestration, with explicit normal-only training filtering and snapshot propagation, or to reject modes that are not wired instead of reporting successful training. Add an integration test that starts a no-runner training job with one small configured episode, asserts a nonzero PPO/update or an explicit documented collection mode, and verifies the requested artifact is created only after compatible weights exist; also assert truncated records never reach PPO.

### CRITICAL — The exported application EvaluationService is not the required evaluator (**confirmed**)

`C:\Users\ozone\Desktop\GameContentsCapstone\GameContentsCapstonedesign\bang_rl\app\__init__.py` exports `services.EvaluationService`. Its `run` implementation in `app/services.py` constructs RandomAgents when no injected agents are supplied, runs `DummyVecEnv`, and computes `wins` from whether a terminal result has a non-null `winning_team`. It does not accept or load a `.bangmodel`, perform artifact compatibility checks, assign the MainAgent to balanced seats, calculate role/hidden-role/emotion metrics, or enforce 500 games for `deterministic_v1`. The separate `bang_rl/evaluation/protocol.py` contains that behavior, but the public application boundary does not delegate to it. A caller using the README’s application service therefore receives a report for a different experiment while the protocol ID can still come from the default config.

The minimal safe fix is to make the application service a thin adapter over `PrimaryEvaluationProtocol`/`CustomEvaluationProtocol`, requiring an artifact for model evaluation and mapping the application DTO to the protocol report. Keep any agent-only simulation as a separately named diagnostic API. Test through `from bang_rl.app import EvaluationService`: use a frozen artifact and a one-game custom protocol seam, assert the artifact is queried, and verify primary configuration rejects non-500/non-balanced settings while custom runs remain separate.

### CRITICAL — DummyVecEnv shares mutable agent state across workers (**confirmed**)

`C:\Users\ozone\Desktop\GameContentsCapstone\GameContentsCapstonedesign\bang_rl\training\vec_env.py`, `DummyVecEnv.__init__`, stores one `agents` sequence and passes the same object to every `WorkerRuntime`. `WorkerRuntime._notify_agents_start`, `_choose_action`, and each agent’s `act` then mutate the same DummyAgent role-belief estimator, EmotionModule event-id set, episode clock, and private RNG from different worker episodes. `DummyVecEnv.step` visits workers sequentially but still uses the shared objects; if two workers are active, the first worker’s event IDs and emotion state are present when the second worker acts. Since event IDs are episode-local, the second worker can silently treat a different episode’s event ID as already processed. Concurrent callers make the same race explicit. This breaks worker independence and means results depend on worker scheduling, violating reproducibility and the privacy/lifecycle boundary.

The minimal safe fix is to construct a fresh agent graph per worker (prefer an agent factory receiving worker/episode seed; otherwise deep-copy a validated template and reseed each private RNG), and never share EmotionModule, RoleBeliefEstimator, or action RNG objects. Add a two-worker test with distinct episode IDs and events that asserts each worker’s processed event IDs, emotion state, role beliefs, and action stream are independent; repeat `step` ordering and compare serialized records for deterministic replay.

### CRITICAL — Reward calculation is not persisted as the canonical step reward (**confirmed**)

`C:\Users\ozone\Desktop\GameContentsCapstone\GameContentsCapstonedesign\bang_rl\data\collector.py`, `EpisodeCollector.record_step`, calculates a `RewardBatch` through `reward_runtime` or `reward_calculator`, extracts only `rewards`, version, and ID for `reward_breakdowns`, and then constructs `CanonicalStep` with `reward=float(values.get("reward", 0.0))`. When the incoming `ActionResult` has its default reward of `0.0`—the normal case when a separate calculator is configured—the canonical step still stores zero even though its breakdown contains shaping and terminal totals. `NPZTensorCacheWriter._materialize` copies `step.reward` into the `rewards` tensor, so the error reaches derived training data and PPO consumers.

The minimal safe fix is to resolve the acting agent’s `RewardBreakdown.total` from the calculated batch and use it for `CanonicalStep.reward`, while preserving the full batch in `reward_breakdowns`; if no reward calculator is configured, retain the result’s scalar reward. Add a collector test with a nonzero configured shaping rule and a zero-reward `ActionResult`, then assert both canonical `step.reward` and NPZ `rewards` contain the configured total, including terminal reward on normal termination and zero terminal reward on truncation.

### HIGH — PPO conversion rejects the ledger’s domain Action representation (**confirmed**)

`C:\Users\ozone\Desktop\GameContentsCapstone\GameContentsCapstonedesign\bang_rl\training\pending_transition.py`, `PendingTransitionLedger.begin_action`, serializes a domain `Action` using `Action.to_dict()`, yielding fields such as `action_type`, `actor_idx`, and `target_idx`. `C:\Users\ozone\Desktop\GameContentsCapstone\GameContentsCapstonedesign\bang_rl\training\ppo_trainer.py`, `PPOTransition.from_committed`, handles a mapping by looking for an `action` key and otherwise passes the whole mapping to `_action`; `_action` immediately calls `int(value)`. Thus a real ledger transition created with `bang_rl.env.Action` cannot be converted to a PPO transition, even though scalar actions happen to work in the isolated tests.

The minimal safe fix is to normalize all action forms once at the ledger/PPO boundary: accept a discrete `action` field, or decode `action_type=PASS/BANG` plus `target_idx` to `0`/`target_idx+1`, and reject inconsistent representations. Add an integration test that begins a ledger transition with `Action.pass_action` and `Action.bang`, commits a result, calls `PPOTransition.from_committed`, and verifies the discrete action and mask are preserved.

### HIGH — Agent elimination closes an episode as normal termination (**confirmed**) 

`C:\Users\ozone\Desktop\GameContentsCapstone\GameContentsCapstonedesign\bang_rl\training\pending_transition.py`, `PendingTransitionLedger.eliminate_agent`, delegates to `finish_episode` with `terminated=True`. MainAgent elimination is not the environment’s normal win/loss condition: the game may continue with the other four players, and the final team result must be applied to the actual last pending transition at environment termination. Marking the record terminated at elimination makes it PPO-trainable with no final game result, closes the ledger, prevents later episode results from being recorded, and can apply an override reward to a nonterminal game. The separate `main_agent_eliminated` field exists precisely to represent this distinction.

The minimal safe fix is to add an agent-elimination boundary that finalizes or parks the real pending transition with `main_agent_eliminated=True`, no fabricated next action/state, and no `terminated=True` unless the environment also reports normal termination; retain episode-level pending/result state until the environment closes. Add a test where the MainAgent dies while the environment remains running, then finish normally and assert no fake PASS, no premature terminal flag, and exactly one final terminal reward.

### HIGH — GAE crosses episode, worker, or rollout boundaries (**confirmed**) 

`C:\Users\ozone\Desktop\GameContentsCapstone\GameContentsCapstonedesign\bang_rl\training\ppo_trainer.py`, `PPOTrainer.update`, sorts all selected transitions by `(worker_id, episode_id, environment_step, transition_id)` and calls `compute_gae` once. `compute_gae` resets only on `terminated`, `truncated`, or `trainable=False`; it has no boundary input for a new worker, episode, or rollout. Any nonterminal transition at a rollout cutoff or a partially supplied episode therefore propagates its `running` advantage into the next sorted record, even if that record belongs to another episode/worker. The code can also use the next record’s recursive GAE contribution despite each transition having an independently computed bootstrap value.

The minimal safe fix is to segment GAE by `(worker_id, episode_id, rollout_id)` and reset at every segment boundary, while still bootstrapping an actual nonterminal next state within a segment. Alternatively add an explicit `boundary`/`continuation` tensor to `compute_gae`. Add a two-episode/two-worker test with nonterminal first records and compare each segment’s result with independent `compute_gae` calls; add a rollout-cutoff test that uses the supplied next value but does not carry advantage into the next segment.

### HIGH — Primary evaluation ignores `evaluation.opponent_preset` (**confirmed**) 

`C:\Users\ozone\Desktop\GameContentsCapstone\GameContentsCapstonedesign\bang_rl\evaluation\protocol.py`, `PrimaryEvaluationProtocol.run`, assigns `preset = self.config.preset` and passes it to every `_run_game`; the `EvaluationConfig.opponent_preset` and `opponent_presets` mapping are not consulted. `CustomEvaluationProtocol._preset` correctly resolves the requested preset, so the two public protocol paths disagree. A primary run configured with a different opponent preset can silently evaluate against the default behavior while reporting the requested preset ID in its run identity.

The minimal safe fix is to share `_preset` resolution with the primary path (or explicitly restrict primary configuration to the default preset and reject other values). Test two distinct presets with observably different DummyAgent behavior and assert the primary run uses the selected one or fails validation rather than silently substituting `config.preset`.

### MEDIUM — Per-game environments and supplied logger handlers are not closed (**confirmed**) 

`C:\Users\ozone\Desktop\GameContentsCapstone\GameContentsCapstonedesign\bang_rl\evaluation\protocol.py`, `PrimaryEvaluationProtocol._run_game`, creates an environment but never calls `close` on any return path. Each default environment creates invalid-action, episode-event, and termination `StructuredLogger` handlers; application/vector factories also pass custom handlers whose ownership is not transferred to `BangEnvironment`, so `BangEnvironment.close` does not close those handlers. A 500-game evaluation can retain hundreds or thousands of logger objects/streams and continue emitting through stale handlers. This is a lifecycle and performance defect, not just cleanup style.

The minimal safe fix is a `try/finally` around each game that closes the environment and any logger resources owned by the factory; define ownership explicitly so a caller-supplied logger is not unexpectedly closed. Add a test with a counting environment/logger that asserts close exactly once on normal, truncation, and exception paths, and a 500-game smoke test that checks handler count remains bounded.

### MEDIUM — Direct short environments silently suppress required long-game diagnostics (**confirmed**) 

`C:\Users\ozone\Desktop\GameContentsCapstone\GameContentsCapstonedesign\bang_rl\env\environment.py`, `BangEnvironment.__init__`, sets `_diagnostics_enabled=False` when the default warning/critical thresholds cannot be reached by a short direct `max_episode_steps`; it comments that this is for ad-hoc fixtures. The configuration schema correctly rejects invalid threshold order, but callers using the public constructor can bypass that validation and receive no diagnostic or configuration error. This makes the same threshold configuration behave differently depending on construction path.

The minimal safe fix is to validate threshold order consistently in the constructor and require callers/tests to pass explicitly valid short thresholds, or derive short-test thresholds only through an explicit test option that cannot be mistaken for production configuration. Add a direct-constructor test asserting invalid threshold order raises and a valid short-threshold test asserting each crossing is logged once.

### MEDIUM performance — Public observation rebuilds the entire event history per action (**confirmed**) 

`C:\Users\ozone\Desktop\GameContentsCapstone\GameContentsCapstonedesign\bang_rl\env\types.py`, `EnvironmentState.to_public`, scans the full immutable `event_log`, calls `to_public_dict()` for every retained event, and constructs viewer-specific arrays each time `BangEnvironment.observe` is called. With the documented unlimited event history, this repeats the same work for every player action and makes long episodes quadratic in retained-event count; `WorkerRuntime` then deep-copies the result again. This is especially costly in headless collection and evaluation.

The contract-preserving optimization is to cache an immutable public event projection in the state transition, or use structural sharing plus a viewer-specific shallow DTO that only copies newly appended events. Keep the returned arrays/events detached from callers. Add a long-history benchmark and an immutability test comparing cached and uncached observations.

### MEDIUM performance — `read_jsonl` rereads the file for every line (**confirmed**) 

`C:\Users\ozone\Desktop\GameContentsCapstone\GameContentsCapstonedesign\bang_rl\runtime\logging.py`, `read_jsonl`, computes `Path(path).read_text(...).splitlines()` once for iteration and again inside every malformed-line check. Large training logs therefore incur repeated full-file reads and can become quadratic in file size.

The minimal safe fix is to store `lines = Path(path).read_text(...).splitlines()` once, then use `line_number == len(lines)` for trailing-partial handling. Add a test for valid records, a malformed middle line, and a malformed final line; a large-file benchmark should show linear I/O.

## Optimization opportunities that preserve documented contracts

The following are **likely performance opportunities**, not contract changes:

`GRUEncoder.forward` in `C:\Users\ozone\Desktop\GameContentsCapstone\GameContentsCapstonedesign\bang_rl\agents\main_agent\encoder.py` compacts streams in a Python loop before packing them. Batch compaction with indexed tensor operations, or a mask-aware recurrent implementation that preserves left-padding semantics, can reduce CPU overhead without changing valid-mask behavior or output shapes.

`ParquetCanonicalShardWriter.write_episode` in `C:\Users\ozone\Desktop\GameContentsCapstone\GameContentsCapstonedesign\bang_rl\data\parquet_writer.py` serializes a candidate shard to measure the byte limit and serializes it again during commit. Reusing the measured bytes when the candidate is committed, while retaining the exact compressed-byte rollover rule, avoids duplicate Arrow/Zstandard work.

`NPZTensorCacheWriter._materialize` in `C:\Users\ozone\Desktop\GameContentsCapstone\GameContentsCapstonedesign\bang_rl\data\tensor_cache.py` accumulates a Python dictionary per step and then stacks every field. A pre-sized or chunked array builder can lower peak memory for large shards, provided deterministic episode/step ordering, dtypes, and cache hashes remain unchanged.

## Validation limits

The repository contains a broad pytest suite, including environment/AEC, agents, emotion/reward runtime, collector/Parquet/NPZ, PPO math, vector workers, artifacts, application services, and GUI controller tests. The attempted full validation command `python -m pytest -q` did not start: the workspace PowerShell execution wrapper echoed malformed command text and exited with code `-1` before pytest output. No source changes were made, so no post-change test run was possible. The findings above are based on direct source tracing and existing test inspection; the added tests described in each section should be run in a normal shell after the runner issue is resolved.

The current tests also explain why these defects can pass CI: application tests inject a custom `TrainingService` runner, application evaluation tests inject a custom runner, vector tests use no mutable DummyAgent tuple, collector tests pass an explicit `reward_batch`, and PPO tests construct scalar actions and already-complete transitions. None exercises the failing default integrations.
